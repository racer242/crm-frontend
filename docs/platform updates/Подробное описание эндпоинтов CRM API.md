# Полное описание эндпоинтов CRM API промо-инстанса

Свод эндпоинтов CRM API с учётом всех согласованных правок. Это предварительная спецификация для финального согласования.

---

## 0. Общие соглашения

| Аспект                   | Значение                                                    |
| ------------------------ | ----------------------------------------------------------- |
| Префикс всех эндпоинтов  | `/api/v1/crm/`                                              |
| Аутентификация           | Подпись запроса HMAC-SHA256 — см. «Модель доступа»          |
| `Content-Type`           | `application/json` — для запросов с телом                   |
| Конверт успеха           | `{"status":"ok","data":{...}}`                              |
| Конверт ошибки           | `{"error":{"code","message","details?"}}`                   |
| Идентификаторы           | UUID v7                                                     |
| Даты                     | ISO 8601                                                    |
| Имена полей              | `snake_case`                                                |

### Модель доступа

- Свод **единый** для всех доверенных бэкендов группировки CRM.
- Граница безопасности — отделение внешних запросов от запросов группировки.
- Аутентификация — **подпись каждого запроса**, а не голый ключ в заголовке. Обмен односторонний (CRM → инстанс), пользовательской авторизации здесь нет, а в запросах ходят персональные данные участников, поэтому проверка складывается из трёх независимых слоёв: подпись подтверждает авторство и целостность, окно времени с одноразовым `nonce` не даёт переиграть перехваченный запрос, список адресов отсекает чужой источник.

#### Заголовки аутентификации (обязательны для всех эндпоинтов)

| Заголовок          | Значение                                                            |
| ------------------ | ------------------------------------------------------------------- |
| `X-Crm-Key-Id`     | Идентификатор ключа, выданного инстансом                             |
| `X-Crm-Timestamp`  | Время отправки, unix-секунды                                         |
| `X-Crm-Nonce`      | Разовая строка запроса, `[A-Za-z0-9._:-]{8,128}`                     |
| `X-Crm-Signature`  | `hash_hmac('sha256', канон, секрет)`, hex в нижнем регистре          |

#### Канонический вид подписи

Подписываются пять строк, склеенных `\n`:

```
МЕТОД                 (в верхнем регистре: GET, POST, PATCH, DELETE)
ЦЕЛЬ-ЗАПРОСА          (путь и query ровно так, как отправлены, без нормализации)
sha256(тело)          (hex; для пустого тела — sha256 пустой строки)
TIMESTAMP             (значение заголовка X-Crm-Timestamp)
NONCE                 (значение заголовка X-Crm-Nonce)
```

Подписывается **цель запроса целиком**, вместе с query: иначе подменой параметров можно было бы переписать фильтры. Хэш тела, а не тело — чтобы канон оставался коротким на больших порциях.

#### Правила проверки

- Расхождение часов CRM и инстанса — не более **5 минут**, иначе `CRM_REQUEST_EXPIRED`.
- `nonce` принимается один раз; повтор — `CRM_REPLAY_DETECTED`.
- Адрес источника сверяется со списком, настроенным на ключ; на проде список обязателен, иначе `CRM_IP_NOT_ALLOWED`.
- Ключи заводятся и ротируются командой `app:crm:client`.

#### Коды ошибок доступа

| HTTP | Код                    | Когда                                     |
| ---- | ---------------------- | ----------------------------------------- |
| 401  | `CRM_AUTH_REQUIRED`    | Не переданы заголовки подписи             |
| 401  | `CRM_KEY_UNKNOWN`      | Ключ неизвестен или отключён              |
| 401  | `CRM_SIGNATURE_INVALID`| Подпись не сошлась                        |
| 401  | `CRM_REQUEST_EXPIRED`  | Метка времени вне допустимого окна        |
| 409  | `CRM_REPLAY_DETECTED`  | Запрос с таким `nonce` уже был обработан  |
| 403  | `CRM_IP_NOT_ALLOWED`   | Адрес источника не разрешён для ключа     |

### Общие параметры пагинации (все списковые эндпоинты)

| Параметр | Где   | Тип | По умолчанию  | Описание        |
| -------- | ----- | --- | ------------- | --------------- |
| `page`   | query | int | 1             | Номер страницы  |
| `limit`  | query | int | 20 (макс 100) | Размер страницы |

### Общий ответ списковых эндпоинтов (в `data`)

| Поле         | Тип    | Описание                                  |
| ------------ | ------ | ----------------------------------------- |
| `items`      | array  | Массив элементов                          |
| `pagination` | object | `{page, limit, total_items, total_pages}` |

### 1.1. `GET /api/v1/crm/users` — список участников

**Назначение и принцип:** пагинированный список участников для просмотра и управления в админ-панели. Поддерживает фильтрацию и поиск.

**Запрос:**

| Параметр        | Где   | Тип    | Обяз. | Описание                    |
| --------------- | ----- | ------ | ----- | --------------------------- |
| `page`, `limit` | query | int    | нет   | Пагинация                   |
| `status`        | query | string | нет   | Фильтр по статусу участника |
| `email`         | query | string | нет   | Поиск по почте              |
| `search`        | query | string | нет   | Поиск по имени/почте        |

**Ответ (`data.items[]`):**

| Поле                                    | Тип          | Описание                |
| --------------------------------------- | ------------ | ----------------------- |
| `id`                                    | UUID         | Идентификатор участника |
| `email`                                 | string       | Почта                   |
| `first_name`, `last_name`, `third_name` | string\|null | ФИО                     |
| `status`                                | string       | Статус                  |
| `created_at`                            | datetime     | Дата регистрации        |

### 1.2. `GET /api/v1/crm/users/[id]` — участник подробно (полная карточка)

**Назначение и принцип:** возвращает исчерпывающие данные участника в одном ответе — базовый профиль, расширенную анкету (персональные и паспортные данные, ИНН, СНИЛС), факт согласия и загруженные документы. Это единственное место в CRM API, откуда отдаются экстра-данные участника (отдельного эндпоинта для экстра-данных в CRM API не существует).

**Запрос:**

| Параметр | Где  | Тип  | Обяз. | Описание                |
| -------- | ---- | ---- | ----- | ----------------------- |
| `id`     | path | UUID | да    | Идентификатор участника |

**Ответ (`data`):**

**Базовые данные участника**

| Поле                                    | Тип          | Описание                         |
| --------------------------------------- | ------------ | -------------------------------- |
| `id`                                    | UUID         | Идентификатор участника          |
| `email`                                 | string       | Почта                            |
| `status`                                | string       | Статус участника                 |
| `created_at`                            | datetime     | Дата регистрации                 |
| `first_name`, `last_name`, `third_name` | string\|null | ФИО (базовый профиль)            |
| `phone`                                 | string\|null | Телефон                          |
| `city_id`                               | string\|null | Ключ города в справочнике `dict_cities` |
| `city`                                  | string\|null | Название города для показа       |
| `mailing`                               | string       | Признак рассылки (`"1"` / `"0"`) |
| `points`                                | int          | Текущий баланс баллов            |

**Расширенная анкета (`extra`)**

| Поле                                    | Тип          | Описание                                       |
| --------------------------------------- | ------------ | ---------------------------------------------- |
| `extra.personal.first_name`             | string       | Имя (из расширенной анкеты)                    |
| `extra.personal.last_name`              | string       | Фамилия                                        |
| `extra.personal.third_name`             | string\|null | Отчество                                       |
| `extra.extended.inn`                    | string\|null | ИНН (12 цифр физлицо / 10 юрлицо)              |
| `extra.extended.snils`                  | string\|null | СНИЛС (11 цифр)                                |
| `extra.extended.passport_series_number` | string\|null | Серия и номер паспорта (10 цифр)               |
| `extra.extended.passport_issue_date`    | string\|null | Дата выдачи паспорта                           |
| `extra.extended.passport_issued_by`     | string\|null | Кем выдан паспорт                              |
| `extra.extended.passport_address`       | string\|null | Адрес регистрации                              |
| `extra.agreement`                       | bool         | Факт согласия на обработку персональных данных |
| `extra.documents`                       | object       | Загруженные документы по типам                 |

**Документы (`extra.documents`)** — объект, ключ = тип документа, значение = данные файла.

| Ключ            | Описание                       |
| --------------- | ------------------------------ |
| `passport_main` | Паспорт (первая страница)      |
| `passport_reg`  | Паспорт (разворот регистрации) |
| `inn_scan`      | Свидетельство ИНН              |
| `snils_scan`    | Свидетельство СНИЛС            |

Каждый документ: `{ "file_id": string, "url": string }`.

`url` отдаётся **без префикса версии** (`/users/profile/extra/document/{id}`, решение от 2026-09-07): путь подставляется к базовому адресу API, который `/api/v1` уже содержит. Так же устроены адреса фото чека (`/receipt/{id}/photo/{файл}`) и скана акта (`/prizes/{id}/act/signed`). Чтобы забрать файл, к пути нужно добавить `/api/v1`.

**Примечания:**

- Два набора ФИО независимы и могут отличаться — это разные сущности, так задумано. Оба набора присутствуют в ответе.
- При отсутствии расширенной анкеты `extra` возвращается с пустыми структурами: `personal` и `extended` — пустые значения, `agreement` — `false`, `documents` — пустой объект. Поле `extra` не отсутствует и не `null`.

| ----------------------------------------------- | ---- | ------ | ----- | -------------------------- |
| `users`                                         | body | array  | да    | Массив объектов участников |
| `users[].email`                                 | body | string | да    | Почта                      |
| `users[].first_name`, `last_name`, `third_name` | body | string | нет   | ФИО                        |



**Ответ (`data`):**

### 1.4. `PATCH /api/v1/crm/users/[id]` — изменить данные участника

**Назначение и принцип:** частичное обновление анкетных данных участника администратором.

**Запрос:**

| Параметр                                                          | Где  | Тип    | Обяз. | Описание         |
| ----------------------------------------------------------------- | ---- | ------ | ----- | ---------------- |
| `id`                                                              | path | UUID   | да    | Идентификатор    |
| `first_name`, `last_name`, `third_name`, `phone`, `email`          | body | string | нет   | Обновляемые поля |
| `city_id`                                                         | body | string | нет   | Ключ города из справочника `dict_cities` |
| `status`                                                          | body | string | нет   | Новый статус     |

**Ответ (`data`):** обновлённые поля участника, включая `city_id` и `city`.

Город — ссылка на справочник, а не текст (решение от 2026-09-07): значение проверяется по `dict_cities`, неизвестный или погашенный ключ даёт `422 VALIDATION_ERROR` с полем `city_id`. Прежнее свободнотекстовое поле `city` в запросе **не принимается** — его передача тоже даёт `422`, чтобы город не терялся молча при старом формате запроса.

### 2.2. `POST /api/v1/crm/codes/import` — синхронизация пула кодов

**Назначение и принцип:** синхронизация пула кодов с входящим эталонным списком из справочника кодов. **Пул кодов** — набор, в котором каждый код уникален и может иметь владельца. Входящий список — эталон, пул приводится к нему.

**Логика синхронизации:**

| Ситуация                                            | Действие                                                | Счётчик   |
| --------------------------------------------------- | ------------------------------------------------------- | --------- |
| Код есть в импорте, отсутствует в пуле              | Добавляется в пул (свободный, без владельца)            | `added`   |
| Код есть в импорте и в пуле, атрибуты изменились    | Обновляется на месте (изменение текущей записи)         | `updated` |
| Код есть в импорте и в пуле, атрибуты не изменились | Не изменяется, не учитывается                           | —         |
| Кода нет в импорте, в пуле есть владелец            | Деактивируется: `is_active = false`, запись сохраняется | `updated` |
| Кода нет в импорте, владельца нет                   | Удаляется из пула                                       | `removed` |

**Запрос:**

| Параметр | Где  | Тип   | Обяз. | Описание                        |
| -------- | ---- | ----- | ----- | ------------------------------- |
| `codes`  | body | array | да    | Эталонный список значений кодов |

**Ответ (`data`) — сводка синхронизации:**

| Поле      | Тип | Описание                                                      |
| --------- | --- | ------------------------------------------------------------- |
| `added`   | int | Добавлено новых кодов                                         |
| `updated` | int | Изменено текущих записей (обновление атрибутов + деактивация) |
| `removed` | int | Удалено кодов                                                 |

### 7.2. `POST /api/v1/crm/prizes/import` — синхронизация пула призов

**Назначение и принцип:** синхронизация пула призов с входящим эталонным списком. **Пул призов** — все возможные призы, где каждая запись — один реальный приз (даже если призов одного типа много). Логика синхронизации идентична кодам.

**Логика синхронизации:**

| Ситуация                                             | Действие                                                | Счётчик   |
| ---------------------------------------------------- | ------------------------------------------------------- | --------- |
| Приз есть в импорте, отсутствует в пуле              | Добавляется в пул                                       | `added`   |
| Приз есть в импорте и в пуле, атрибуты изменились    | Обновляется на месте (изменение текущей записи)         | `updated` |
| Приз есть в импорте и в пуле, атрибуты не изменились | Не изменяется, не учитывается                           | —         |
| Приза нет в импорте, приз назначен участнику         | Деактивируется: `is_active = false`, запись сохраняется | `updated` |
| Приза нет в импорте, приз не назначен                | Удаляется из пула                                       | `removed` |

**Запрос:**

| Параметр | Где  | Тип   | Обяз. | Описание                                              |
| -------- | ---- | ----- | ----- | ----------------------------------------------------- |
| `prizes` | body | array | да    | Эталонный список призов (каждый — один реальный приз) |
    
**Ответ (`data`) — сводка синхронизации:**

| Поле      | Тип | Описание                                                      |
| --------- | --- | ------------------------------------------------------------- |
| `added`   | int | Добавлено новых призов                                        |
| `updated` | int | Изменено текущих записей (обновление атрибутов + деактивация) |
| `removed` | int | Удалено призов                                                |

## 8. Розыгрыши

Используются модели и логика из ТЗ «Механика проведения розыгрыша» и «Эндпоинты проведения розыгрышей».

## 9. Очереди задач

Используются модели из ТЗ «Очередь задач промо-инстанса».

**Состояния задач:** `waiting`, `in_flight`, `final_success`, `final_failed`, `manual`.
**Модель доставки:** at-least-once, идемпотентность по `task_id` + `execution_id`.

### Список эндпоинтов раздела

| №   | Эндпоинт                         | Назначение                            |
| --- | -------------------------------- | ------------------------------------- |
| 9.1 | `PUT /api/v1/crm/queue/claim`    | Извлечь пакет задач из очереди (FIFO) |
| 9.2 | `POST /api/v1/crm/queue/results` | Отправить результаты задач            |
| 9.3 | `GET /api/v1/crm/tasks`          | Текущая очередь задач                 |
| 9.4 | `GET /api/v1/crm/tasks/sent`     | Задачи в работе                       |
| 9.5 | `GET /api/v1/crm/tasks/results`  | Очередь результатов                   |

### 9.1. `PUT /api/v1/crm/queue/claim` — извлечь пакет задач (FIFO)

**Назначение и принцип:** пакетный запрос исполнительного бэкенда на получение задач. Атомарно переводит выбранные задачи в `in_flight`, генерирует `execution_id`, рассчитывает `expires_at`. Учитывает `available_at` и `supported_types`. Отдельный запрос, не смешивается с отправкой результатов.

**Запрос:**

| Параметр          | Где  | Тип    | Обяз. | Описание                             |
| ----------------- | ---- | ------ | ----- | ------------------------------------ |
| `worker_id`       | body | string | да    | Идентификатор воркера или экземпляра |
| `supported_types` | body | array  | да    | Поддерживаемые типы задач            |
| `max_tasks`       | body | int    | да    | Максимум задач к получению           |
| `client_version`  | body | string | нет   | Версия клиента                       |
| `request_id`      | body | string | нет   | Идентификатор запроса                |

**Ответ (`data`):**

**Поле `tasks[]`:**

| Поле             | Тип      | Описание             |
| ---------------- | -------- | -------------------- |
| `task_id`        | UUID     | Идентификатор задачи |
| `execution_id`   | UUID     | Идентификатор выдачи |
| `type`           | string   | Тип задачи           |
| `version`        | string   | Версия схемы         |
| `payload`        | object   | Данные задачи        |
| `attempt_number` | int      | Номер попытки        |
| `created_at`     | datetime | Время создания       |

**Поле `meta`:**

| Поле                       | Тип      | Описание                                  |
| -------------------------- | -------- | ----------------------------------------- |
| `has_more`                 | bool     | Есть ли ещё задачи в очереди              |
| `next_claim_delay_seconds` | int      | Рекомендация по паузе до следующего claim |
| `throttled`                | bool     | Признак необходимости ограничить выдачу   |
| `server_time`              | datetime | Время сервера промо-инстанса              |

---

### 9.2. `POST /api/v1/crm/queue/results` — отправить результаты задач

**Назначение и принцип:** пакетная отправка результатов выполнения задач из исполнительного бэкенда. Для каждого результата проверяется существование задачи, состояние, совпадение `execution_id`. Применяется с учётом идемпотентности.

**Запрос:**

| Параметр                        | Где  | Тип    | Обяз. | Описание                                          |
| ------------------------------- | ---- | ------ | ----- | ------------------------------------------------- |
| `worker_id`                     | body | string | да    | Идентификатор воркера                             |
| `results[]`                     | body | array  | да    | Массив результатов                                |
| `results[].task_id`             | body | UUID   | да    | Идентификатор задачи                              |
| `results[].execution_id`        | body | UUID   | да    | Идентификатор выдачи                              |
| `results[].outcome`             | body | string | да    | `success` / `retryable_failure` / `fatal_failure` |
| `results[].result_data`         | body | object | нет   | Данные результата                                 |
| `results[].error_code`          | body | string | нет   | Код ошибки                                        |
| `results[].error_message`       | body | string | нет   | Сообщение ошибки                                  |
| `results[].retry_after_seconds` | body | int    | нет   | Задержка повтора                                  |

**Ответ (`data`):**

| Поле                | Тип          | Описание                                                 |
| ------------------- | ------------ | -------------------------------------------------------- |
| `results[]`         | array        | Обработанные результаты                                  |
| `results[].task_id` | UUID         | Идентификатор задачи                                     |
| `results[].status`  | string       | `accepted` / `duplicate` / `stale` / `unknown` / `error` |
| `results[].message` | string\|null | Пояснение                                                |
