# ТЗ: Панель управления

## Часть 2. Функциональные возможности панели управления

Панель управления — административный интерфейс для всех управляющих функций платформы. Эта часть описывает, что администратор может делать через панель и через какие компоненты это реализуется.

---

## 1. Модель работы панели

### 1.1. Два канала взаимодействия

Панель работает с двумя видами бэкендов. Каналы принципиально различаются по назначению.

| Канал | Компонент | Что управляется |
|---|---|---|
| Канал конфигурации | Управляющий бэкенд | Кампании, инстансы, настройки логики, справочники, пулы призов, ресурсы (контент), запуск и мониторинг розыгрышей |
| Канал операционных данных | Бэкенды промо-инстансов (административный контур) | Участники, чеки, призы, акты, розыгрыши на инстансе, очередь задач, события, обратная связь |

### 1.2. Разделение ответственности каналов

| Аспект | Канал конфигурации | Канал операционных данных |
|---|---|---|
| Источник правды | Управляющий бэкенд | Бэкенд инстанса |
| Направление поставки данных | Управляющий бэкенд пушит в инстансы | Панель читает и правит данные инстанса |
| Характер данных | Конфигурационные (настройки, справочники, контент) | Операционные (участники, чеки, призы, розыгрыши) |
| Аутентификация панели | Пользовательская сессия (через источник пользователей) | Подпись запроса к административному контуру инстанса |

### 1.3. Принцип: конфигурация не правится на инстансе

Панель не предоставляет редактирование настроек логики и справочников напрямую на инстансе. Источник правды — управляющий бэкенд. Панель редактирует конфигурацию в канале конфигурации, а управляющий бэкенд поставляет её в инстансы. Через канал инстанса панель может только просматривать текущее состояние конфигурации.

## 2. Выбор контекста работы

### 2.1. Иерархия контекста

Платформа организована иерархически: кампания содержит один или несколько инстансов. Перед работой с операционными данными администратор выбирает контекст.

| Уровень | Что выбирается | Откуда берутся данные |
|---|---|---|
| Кампания | Кампания для работы | Управляющий бэкенд |
| Инстанс | Конкретный инстанс внутри кампании | Управляющий бэкенд (реестр инстансов кампании) |

### 2.2. Реестр инстансов

Для работы с инстансом панель должна знать его параметры. Реестр инстансов ведётся в управляющем бэкенде.

| Параметр инстанса | Назначение для панели |
|---|---|
| Идентификатор инстанса | Выбор инстанса |
| Название | Отображение в интерфейсе |
| Принадлежность к кампании | Группировка инстансов |
| Базовый адрес | Куда отправлять запросы административного контура |
| Признак активности | Доступен ли инстанс для работы |
| Состояние последней синхронизации | Информация о актуальности конфигурации инстанса |

### 2.3. Привязка доступа к инстансам

Для обращения к административному контуру инстанса панель использует выданный инстансом ключ. Панель должна быть сконфигурирована идентификатором ключа и секретом подписи для каждого инстанса (или группы инстансов). Секреты не передаются по сети в открытом виде и хранятся на стороне панели безопасно.

## 3. Функциональные возможности через управляющий бэкенд

Все операции этого раздела выполняются в канале конфигурации. Данные управляются средствами интерфейса управления, а поставка в инстансы — задача управляющего бэкенда.

### 3.1. Управление кампаниями и инстансами

| Действие администратора | Описание |
|---|---|
| Просмотр списка кампаний | Обзор кампаний платформы |
| Просмотр инстансов кампании | Список инстансов с их состоянием |
| Регистрация инстанса | Добавление инстанса в кампанию с базовым адресом |
| Управление активностью инстанса | Включение/выключение поставки данных в инстанс |
| Просмотр состояния синхронизации | Время, статус и ошибки последней синхронизации каждого инстанса |

### 3.2. Управление настройками логики

Настройки логики сгруппированы по разделам. Панель предоставляет формы редактирования.

| Группа настроек | Что редактируется |
|---|---|
| Кампания | Название кампании, дата начала, дата окончания, часовой пояс |
| Регистрация и авторизация | Время жизни кода подтверждения, максимум попыток ввода, длительность блокировки, время жизни токенов доступа и обновления |
| Розыгрыши | Источники шансов |

**Принцип:** панель валидирует вводимые значения, сохраняет изменения в управляющем бэкенде и инициирует поставку в инстансы.

### 3.3. Управление справочниками

Справочники ведутся в канале конфигурации. Панель предоставляет управление записями.

| Справочник | Назначение |
|---|---|
| Товары акции | Товары, участвующие в акции |
| Регионы | Регионы для анкет |
| Города | Города для анкет |
| Причины отклонения | Причины отклонения чеков и кодов |
| Темы обратной связи | Темы обращений |
| Шаблоны писем | Тексты уведомлений |
| Источники трафика | Источники переходов |
| Типы игр | Типы игр со схемой настроек |

**Примечание:** каталог типов призов (`dict_prizes`) управляется через отдельный раздел управления пулами призов.

### 3.4. Управление пулами призов

Пулы призов ведутся в канале конфигурации. Панель предоставляет отдельные операции управления.

| Эндпоинт | Метод | Назначение |
|---|---|---|
| `/api/v1/directory/prizes` | GET | Получить справочник призов |
| `/api/v1/directory/prizes` | POST | Добавить приз |
| `/api/v1/directory/prizes/import` | POST | Импорт призов из файла |
| `/api/v1/directory/prizes/[id]` | PATCH | Изменить приз |
| `/api/v1/directory/prizes/[id]` | DELETE | Удалить приз |

### 3.5. Управление ресурсами (контентом)

Ресурсы — контент для фронтенда инстанса. Управление ведётся в канале конфигурации.

| Действие администратора | Описание |
|---|---|
| Управление текстовыми ресурсами | Правила акции, слоганы, тексты страниц |
| Управление изображениями | Изображения для фронтенда |
| Управление структурированными данными | Наборы данных для фронтенда |
| Управление документами и файлами | Документы для просмотра и файлы для скачивания |
| Разграничение по уровням | Глобальные ресурсы, ресурсы кампании, ресурсы инстанса |

**Принцип уровней:** ресурс с одним ключом может существовать на нескольких уровнях; более специфичный уровень переопределяет более общий (инстанс > кампания > глобальный). Инстанс получает плоский список без пометок об уровне.

### 3.6. Синхронизация конфигурации

Поставка конфигурации — инициатива управляющего бэкенда. Панель может запустить синхронизацию вручную.

| Способ запуска | Когда | Кто инициирует |
|---|---|---|
| По событию изменения | При сохранении управляемых данных | Система автоматически |
| По расписанию | Периодическая полная сверка | Система автоматически |
| Вручную | Принудительная синхронизация | Администратор через панель |

**Эндпоинт ручного запуска синхронизации:**

| Параметр | Где | Тип | Обяз. | Описание |
|---|---|---|---|---|
| `id` | path | UUID | да | Идентификатор кампании |
| `instance_id` | query | UUID | нет | Синхронизировать только этот инстанс; иначе все активные |

**Ответ** содержит сводку по каждому инстансу: статус синхронизации, сводку по настройкам и справочникам, ошибки, длительность.

### 3.7. Запуск розыгрышей

Розыгрыш проводится управляющим бэкендом. Панель инициирует проведение.

| Действие администратора | Эндпоинт | Метод | Описание |
|---|---|---|---|
| Запуск розыгрыша | `api/v1/raffle/run` | POST | Запустить процесс розыгрыша на управляющем бэкенде |

**Принцип:** администратор нажимает кнопку старта в интерфейсе панели. Панель отправляет запрос в управляющий бэкенд. Запрос строго контролируется от повторного и множественного нажатия.

**Последовательность после запуска** (выполняется управляющим бэкендом, панель только мониторит):
1. Получение параметров выборки с инстанса.
2. Бронирование розыгрыша и шансов.
3. Забор шансов.
4. Выполнение алгоритма розыгрыша.
5. Отправка победителей порциями на инстанс.
6. Передача протокола розыгрыша.

### 3.8. Мониторинг проведения розыгрышей

Панель отслеживает процесс проведения розыгрышей на управляющем бэкенде.

| Действие администратора | Эндпоинт | Метод | Описание |
|---|---|---|---|
| Список проводимых розыгрышей | `api/v1/raffles` | GET | Все розыгрыши, проводящиеся на сервисе |
| Статус проведения розыгрыша | `api/v1/raffle/[id]` | GET | Статус проведения конкретного розыгрыша |

## 4. Функциональные возможности через бэкенды инстансов

Все операции этого раздела выполняются в канале операционных данных через административный контур выбранного инстанса (префикс `/api/v1/crm/`).

### 4.1. Управление участниками

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Список участников | `/api/v1/crm/users` | GET |
| Полная карточка участника | `/api/v1/crm/users/[id]` | GET |
| Импорт участников | `/api/v1/crm/users/import` | POST |
| Изменение данных участника | `/api/v1/crm/users/[id]` | PATCH |
| Редактирование документов участника | `/api/v1/crm/users/[id]/docs` | PATCH |
| Редактирование расширенных данных участника | `/api/v1/crm/users/[id]/extra` | PATCH |

**Полная карточка участника** — единственное место, откуда отдаются экстра-данные: базовый профиль, расширенная анкета (паспортные данные, ИНН, СНИЛС), факт согласия, загруженные документы.

### 4.2. Управление чеками и модерация

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Список чеков | `/api/v1/crm/receipts` | GET |
| Чек подробно | `/api/v1/crm/receipts/[id]` | GET |
| Продукция в чеке | `/api/v1/crm/receipts/[id]/products` | GET |
| Модерация чека (принять/отклонить/приостановить) | `/api/v1/crm/receipts/[id]` | PATCH |
| Удаление чека | `/api/v1/crm/receipts/[id]` | DELETE |
| Чеки участника | `/api/v1/crm/users/[id]/receipts` | GET |

**Модерация:** ручная модерация чеков выполняется в панели. Автоматическая модерация — в системе очереди задач. В обоих случаях сигналом для генерации шанса служит успешная регистрация чека.

### 4.3. Управление призами и актами

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Список призов | `/api/v1/crm/prizes` | GET |
| Приз подробно | `/api/v1/crm/prizes/[id]` | GET |
| Призы участника | `/api/v1/crm/users/[id]/prizes` | GET |
| Назначение приза участнику | `/api/v1/crm/users/[id]/prizes` | POST |
| Отзыв приза у участника | `/api/v1/crm/users/[user_id]/prizes/[prize_id]` | DELETE |
| Акты участника | `/api/v1/crm/users/[id]/acts` | GET |
| Список актов | `/api/v1/crm/acts` | GET |
| Акт подробно | `/api/v1/crm/acts/[id]` | GET |
| Добавление акта | `/api/v1/crm/acts` | POST |
| Обновление акта | `/api/v1/crm/acts/[id]` | PATCH |
| Удаление акта | `/api/v1/crm/acts/[id]` | DELETE |

### 4.4. Управление розыгрышами на инстансе

Розыгрыши создаются и управляются на инстансе. Проведение — задача управляющего бэкенда.

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Список розыгрышей | `/api/v1/crm/raffles` | GET |
| Создание розыгрыша | `/api/v1/crm/raffles` | POST |
| Подробности розыгрыша | `/api/v1/crm/raffles/[id]` | GET |
| Редактирование розыгрыша (только в статусе черновика) | `/api/v1/crm/raffles/[id]` | PATCH |
| Публикация розыгрыша | `/api/v1/crm/raffles/publish` | POST |
| Аннулирование розыгрыша | `/api/v1/crm/raffles/annul` | POST |
| Протокол розыгрыша | `/api/v1/crm/raffles/protocol` | GET |
| Список всех шансов | `/api/v1/crm/raffles/chances` | GET |
| Шансы под условиями розыгрыша | `/api/v1/crm/raffles/[id]/chances` | GET |
| Количество шансов под условиями | `/api/v1/crm/raffles/[id]/chances/count` | GET |
| Участники розыгрышей | `/api/v1/crm/raffles/participants` | GET |
| Участники конкретного розыгрыша | `/api/v1/crm/raffles/[id]/participants` | GET |

**Предпросмотр выборки:** при создании розыгрыша администратор задаёт параметры и сразу видит, сколько шансов подпадает под условия. Это реализуется через запросы шансов и их количества до бронирования.

**Жизненный цикл розыгрыша:** черновик → в работе → завершён → опубликован; отдельно — аннулирован. Редактирование разрешено только в статусе черновика.

### 4.5. Просмотр конфигурации инстанса

Панель может просматривать текущее состояние конфигурации инстанса (без редактирования — редактирование в канале конфигурации).

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Текущие настройки инстанса | `/api/v1/crm/settings` | GET |
| Список справочников инстанса | `/api/v1/crm/dictionaries` | GET |
| Записи справочника | `/api/v1/crm/dictionaries/[name]` | GET |
| Список ресурсов инстанса | `/api/v1/crm/resources` | GET |
| Ресурс по ключу | `/api/v1/crm/resources/[key]` | GET |

### 4.6. Мониторинг очереди задач

Панель отслеживает состояние очереди задач инстанса. Исполнение задач — задача управляющего бэкенда.

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Текущая очередь задач | `/api/v1/crm/tasks` | GET |
| Задачи в работе | `/api/v1/crm/tasks/sent` | GET |
| Очередь результатов | `/api/v1/crm/tasks/results` | GET |

**Примечание:** панель не извлекает задачи и не отправляет результаты — это делает управляющий бэкенд. Панель только мониторит.

### 4.7. Мониторинг событий

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Все события | `/api/v1/crm/log/events` | GET |
| Событие подробно | `/api/v1/crm/log/events/[id]` | GET |
| Журнал событий участника | `/api/v1/crm/users/[id]/log/events` | GET |

### 4.8. Обратная связь

| Действие администратора | Эндпоинт | Метод |
|---|---|---|
| Список всех сообщений | `/api/v1/crm/messages` | GET |
| Сообщения участника | `/api/v1/crm/users/[id]/messages` | GET |

## 6. Ключевые принципы функциональности

| Принцип | Содержание |
|---|---|
| Разделение каналов | Конфигурация управляется через управляющий бэкенд, операционные данные — через бэкенды инстансов |
| Источник правды для конфигурации | Управляющий бэкенд; панель не правит конфигурацию на инстансе напрямую |
