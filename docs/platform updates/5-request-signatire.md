# Подпись запросов к административному контуру

## 1. Общий принцип

Обмен односторонний: запросы идут только от внешних сервисов группировки к инстансу, исходящих вызовов инстанс не делает. Значит, вся защита сосредоточена на приёме.

Проверка навешена на весь префикс административного контура целиком, а не на отдельные обработчики. Новый эндпоинд под этим префиксом защищён самим фактом своего адреса — забыть проверку невозможно. Неподписанный запрос получает отказ **до маршрутизации**, поэтому по коду ответа нельзя перебрать состав контура: любой путь под префиксом без подписи отвечает одинаково.

## 2. Три слоя проверки

Проверка выполняется в порядке от дешёвого к дорогому. Каждый слой закрывает свою угрозу, и одного слоя недостаточно.

| Слой                                     | От чего защищает                    | Почему одного слоя мало                                            |
| ---------------------------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| Подпись запроса                          | Подмена тела, метода и цели запроса | Сама по себе не мешает отправить перехваченный запрос второй раз   |
| Окно времени + одноразовый идентификатор | Повтор перехваченного запроса       | Без подписи одноразовый идентификатор можно «сжигать» чужому ключу |
| Список разрешённых адресов               | Чужой источник                      | Адрес подделывается, и у внешнего сервиса он может меняться        |

## 3. Заголовки запроса

Все четыре заголовка обязательны для каждого запроса к административному контуру:

| Заголовок         | Значение                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| `X-Crm-Key-Id`    | Идентификатор ключа, выданного инстансом                                                                           |
| `X-Crm-Timestamp` | Время отправки, `unix`-секунды                                                                                     |
| `X-Crm-Nonce`     | Разовая строка запроса; допустимы буквы, цифры, точка, подчёркивание, двоеточие, дефис; длина от 8 до 128 символов |
| `X-Crm-Signature` | Подпись запроса, шестнадцатеричная строка в нижнем регистре                                                        |

Плюс обязателен заголовок версии обмена `X-Exchange-Version` (см. раздел 6).

## 4. Канонический вид подписи

Подпись вычисляется как хеш с ключом от пяти строк, склеенных символом перевода строки:

| Строка | Содержание                                                                       |
| ------ | -------------------------------------------------------------------------------- |
| 1      | Метод запроса в верхнем регистре                                                 |
| 2      | Цель запроса: путь и параметры ровно так, как отправлены, без нормализации       |
| 3      | Хеш тела запроса, шестнадцатеричная строка; для пустого тела — хеш пустой строки |
| 4      | Метка времени (значение заголовка `X-Crm-Timestamp`)                             |
| 5      | Одноразовый идентификатор (значение заголовка `X-Crm-Nonce`)                     |

**Обоснование правил формирования канона:**

| Правило                                                          | Обоснование                                                                                                                                |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Подписывается цель запроса целиком, вместе с параметрами         | Иначе подменой параметров можно переписать фильтры и вытащить не тот срез данных                                                           |
| Цель передаётся как отправлена, без нормализации                 | Внешний сервис подписывает ту строку, которую кладёт в строку запроса; договариваться о порядке параметров и правилах кодирования не нужно |
| Хеш тела, а не само тело                                         | Канон остаётся коротким на порциях в мегабайты                                                                                             |
| Метка времени и одноразовый идентификатор внутри подписи         | Иначе их можно подменить, и защита от повтора обходится                                                                                    |
| Сравнение подписей выполняется через функцию постоянного времени | Подбор подписи по времени ответа невозможен                                                                                                |

## 5. Правила проверки

| Правило                   | Значение                                                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Окно времени              | Расхождение часов внешнего сервиса и инстанса — не более 5 минут, иначе запрос отклоняется                                                                                                                                     |
| Одноразовый идентификатор | Принимается один раз; повтор — ошибка повтора                                                                                                                                                                                  |
| Список адресов            | Адрес источника сверяется со списком, настроенным на ключ; на боевом сервере список обязателен                                                                                                                                 |
| Ограничение частоты       | 600 запросов в минуту с адреса; порог высокий, потому что выкачивание выборки и заливка порций — легально частые запросы; лимит здесь не про бизнес-логику, а про то, чтобы неподписанный поток не доходил до базы за секретом |

## 6. Версия обмена

Каждый запрос несёт заголовок `X-Exchange-Version` в формате `A.B.C`. Инстанс с версией `V` принимает запрос, если выполняется условие: `B <= V <= A`.

| Часть версии | Название                                   | Когда меняется                                                         |
| ------------ | ------------------------------------------ | ---------------------------------------------------------------------- |
| `A`          | Актуальная версия                          | При структурных изменениях формата обмена                              |
| `B`          | Минимальная поддерживаемая версия инстанса | Когда поддержка старых версий инстансов прекращается                   |
| `C`          | Итерация, не влияющая фатально             | При внутренних уточнениях; в решении принять или отказать не участвует |

Версия обмена **не входит в подпись запроса**: канон хеша с ключом менять не стали. Значит, версию по дороге технически можно подменить, но риск здесь только в ложном отказе — сами данные по-прежнему защищены подписью.

## 7. Порядок проверки в конвейере

Проверки выполняются в строгом порядке:

| Шаг | Проверка                                  |
| --- | ----------------------------------------- |
| 1   | Ключ (известен ли, активен ли)            |
| 2   | Адрес (входит ли в список разрешённых)    |
| 3   | Окно времени                              |
| 4   | Формат одноразового идентификатора        |
| 5   | **Подпись**                               |
| 6   | **Версия обмена**                         |
| 7   | Одноразовый идентификатор (однократность) |

**Порядок выбран не случайно:**

- Версия проверяется **после подписи** — чтобы неаутентифицированный запрос не мог выяснить версию инстанса по коду ответа.
- Версия проверяется **до занятия одноразового идентификатора** — отклонённый по версии запрос должен остаться повторяемым: внешний сервис правит заголовок версии и шлёт тот же запрос с тем же одноразовым идентификатором и меткой времени. Если бы идентификатор занимался раньше, отказ по версии превращал бы повтор в ошибку повтора.

## 8. Ключи доступа

Ключи — сущности на стороне инстанса, а не переменные окружения. Это обеспечивает ротацию без деплоя, выключение конкретного клиента и след обращений.

| Поле ключа                 | Назначение                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| Идентификатор ключа        | Значение заголовка `X-Crm-Key-Id`; несколько ключей живут одновременно (ротация, разные среды) |
| Секрет подписи             | Секрет для вычисления подписи, шестнадцатеричная строка                                        |
| Список разрешённых адресов | Адреса или подсети; пусто — ограничения по адресу нет                                          |
| Признак активности         | Отзыв ключа мгновенный, выключенный ключ не находится                                          |
| След обращений             | Время последнего обращения, адрес, счётчик запросов — для разбора инцидентов                   |

**Правила эксплуатации:**

- Секрет хранится открытым и хеширован быть не может: по нему пересчитывается подпись входящего запроса.
- Доступ к ключам только у администратора инстанса.
- Ротация — через новую запись или смену секрета: два активных ключа живут рядом, старый выключается после переключения внешнего сервиса на новый.

## 9. Коды ошибок проверки

| Код                       | Статус | Когда                                                                             |
| ------------------------- | ------ | --------------------------------------------------------------------------------- |
| `CRM_AUTH_REQUIRED`       | 401    | Не переданы заголовки подписи или недопустимый формат одноразового идентификатора |
| `CRM_KEY_UNKNOWN`         | 401    | Ключ не найден или отключён                                                       |
| `CRM_SIGNATURE_INVALID`   | 401    | Подпись не сошлась                                                                |
| `CRM_REQUEST_EXPIRED`     | 401    | Метка времени вне допустимого окна (±5 минут)                                     |
| `CRM_REPLAY_DETECTED`     | 409    | Запрос с таким одноразовым идентификатором уже был обработан                      |
| `CRM_IP_NOT_ALLOWED`      | 403    | Адрес источника не разрешён для ключа                                             |
| `CRM_VERSION_REQUIRED`    | 400    | Отсутствует заголовок версии обмена                                               |
| `CRM_VERSION_INVALID`     | 400    | Заголовок версии некорректен                                                      |
| `CRM_VERSION_UNSUPPORTED` | 409    | Версия инстанса вне диапазона версии обмена                                       |

Коды различаются осознанно: контур внутренний, и при интеграции нужно понимать, что именно не сошлось. Каждый отказ пишется в журнал с ключом, адресом и целью запроса.

## 10. Итоговая последовательность для отправителя

Для каждого запроса к административному контуру отправитель:

| Шаг | Действие                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------- |
| 1   | Формирует тело запроса и цель (путь с параметрами)                                                             |
| 2   | Вычисляет хеш тела                                                                                             |
| 3   | Генерирует метку времени (текущие `unix`-секунды)                                                              |
| 4   | Генерирует одноразовый идентификатор (уникальная строка)                                                       |
| 5   | Собирает канонический вид: метод, цель, хеш тела, метка времени, одноразовый идентификатор                     |
| 6   | Вычисляет подпись: хеш с ключом от канона, результат в нижнем регистре                                         |
| 7   | Устанавливает заголовки: идентификатор ключа, метка времени, одноразовый идентификатор, подпись, версия обмена |
| 8   | Отправляет запрос                                                                                              |
