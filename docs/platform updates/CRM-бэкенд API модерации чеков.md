# ТЗ: Обновление эндпоинтов чеков и продукции CRM-бэка (ред. 6 — финальная)

## Ключевое изменение относительно ред. 5

Чек передаётся в CRM для модерации **только с `user_id`** (UUID участника на промо-инстансе). CRM-бэк не получает и не хранит ни имени, ни email, ни кода участника — следовательно, API CRM-бэка не может их отдавать. Это архитектурное ограничение, а не пробел в реализации.

Из этого следует:

- **`user_name`, `email`** убираются из списка чеков.
- **`participant_code`, `first_name`, `last_name`, `email`** убираются из детальной карточки. Остаётся только `user_id` — единственный атрибут участника, доступный CRM.
- **Быстрый поиск (`search`)** в списке сужается: поиск по email и имени невозможен, остаётся только поиск по `receipt_id`.
- **Ссылка на карточку участника** из списка и деталей чека ведёт в раздел «Участники» CRM-бэка по `user_id`; как именно CRM-бэк покажет профиль участника (запросом к промо-инстансу или из собственного кэша) — за пределами этого API.

Фото чека в API не передаются (как и в ред. 5): панель берёт снимки из отдельного источника по ID чека.

## 1. Контекст

Эндпоинты раздела «Чеки» обслуживают админку CRM. Данные чеков хранятся в **CRM-бэке**: CRM забирает чек с промо-инстанса (состав, фискальные данные, `user_id`, магазин), проверяет в ФНС, проводит автомодерацию, при неудаче оставляет на ручной проверке, после решения отправляет обратно в промо-инстанс. Промо-инстанс в этом API не участвует.

**Что CRM знает об участнике:** только его `user_id` (UUID на промо-инстансе). Остальные атрибуты участника (ФИО, email, код) в CRM не хранятся и через эти эндпоинты не отдаются.

## 2. Принципы формата

Формат запросов и ответов — **строго легаси** («Панель управления CRM. Mage Promo»):

| Аспект     | Значение                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| Списки     | Запрос `{first, limit, sort, direction, search, filters}`; ответ `{columns, rows, filters, search, meta}` |
| Ряд списка | `{id, values, props}`; **`id` ряда = внутренний числовой ID CRM**                                         |
| Мета       | `{total_count, first, limit, sort, direction}`; сортировка по одному столбцу                              |
| Мутации    | Ответ `{success, message, error}`                                                                         |
| Деньги     | Рубли с копейками, число с точкой (`590.30`)                                                              |
| Даты       | `registration_date` — ISO datetime; `purchase_date` — дата                                                |
| Статусы    | Код + русское имя из справочника в ответе / `opts` фильтра                                                |

Никаких корреляций с CRM API промо-инстанса.

## 3. Идентификация чека

| Ключ                                   | Где используется                              | Назначение                                                           |
| -------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------- |
| **Внутренний числовой ID** CRM         | `id` ряда в списке, `{id}` в путях эндпоинтов | Идентификация внутри CRM-бэка                                        |
| **`receipt_id`** (UUID промо-инстанса) | Обязательное поле в списке и в деталях        | Связь с записью на промо-инстансе, обратная отправка после модерации |
| **`user_id`** (UUID промо-инстанса)    | Поле в списке и в деталях                     | Единственный атрибут участника, доступный CRM                        |

Миграций нет: ключ ряда остаётся числовым, `receipt_id` и `user_id` добавляются отдельными полями.

## 4. Справочники статусов и причин

### 4.1. `moderation_statuses` (словарь расширен)

| Код          | Русское имя  | Статус |
| ------------ | ------------ | ------ |
| `pending`    | На модерации | есть   |
| `approved`   | Одобрен      | есть   |
| `rejected`   | Отклонен     | есть   |
| `suspended`  | Отложен      | 🆕     |
| `need_photo` | Запрос фото  | 🆕     |

### 4.2. `fns_statuses` (🆕)

| Код        | Русское имя     |
| ---------- | --------------- |
| `no_check` | Не проверен     |
| `wait`     | Ожидает ФНС     |
| `wrong`    | Не найден в ФНС |
| `correct`  | Чек корректный  |

### 4.3. `decline_reasons` (🆕)

| Код           | Русское имя                              |
| ------------- | ---------------------------------------- |
| `WRONG_CHECK` | Чек некорректен                          |
| `NO_PRODUCT`  | Отсутствует акционная продукция          |
| `BAD_PHOTO`   | Фото нечитаемо или не соответствует чеку |
| `DUPLICATE`   | Дубликат                                 |
| `OTHER`       | Другое                                   |

## 5. Эндпоинты раздела

### 5.1. `GET api/receipts` — список чеков

**Запрос:**

```json
{
  "first": 0,
  "limit": 50,
  "sort": "registration_date",
  "direction": "desc",
  "search": "",
  "filters": [{ "id": "moderation_status", "value": ["pending"] }]
}
```

**Столбцы ответа:**

| id                      | title               | type              | sortable |
| ----------------------- | ------------------- | ----------------- | -------- |
| `receipt_id`            | ID чека (пром.)     | string            | да       |
| `registration_date`     | Дата регистрации    | date (datetime)   | да       |
| `purchase_date`         | Дата покупки        | date              | да       |
| `promo_products_count`  | Акционных продуктов | number            | да       |
| `promo_products_amount` | Сумма акционных     | number (currency) | да       |
| `total_amount`          | Сумма чека          | number (currency) | да       |
| `retail_chain`          | Торговая сеть       | string            | да       |
| `fns_status`            | Статус ФНС          | string            | да       |
| `moderation_status`     | Статус модерации    | string            | да       |
| `user_id`               | ID участника        | string (UUID)     | да       |

**Фильтры:**

| id                      | name                         | type     | opts              |
| ----------------------- | ---------------------------- | -------- | ----------------- |
| `moderation_status`     | Статус модерации             | options  | 5 значений (§4.1) |
| `fns_status`            | Статус ФНС                   | options  | 4 значения (§4.2) |
| `retail_chain`          | Торговая сеть                | options  | справочник сетей  |
| `registration_date`     | Период регистрации           | period   | —                 |
| `purchase_date`         | Период покупки               | period   | —                 |
| `promo_products_amount` | Сумма акционных продуктов, ₽ | range    | —                 |
| `has_promo_products`    | Есть акционные продукты      | checkbox | —                 |

**Быстрый поиск (`search`):** точное совпадение по `receipt_id`. Поиск по email и имени невозможен — этих данных в CRM нет.

### 5.2. `GET api/receipts/{id}` — детальная карточка

**Ответ:**

| Поле                                   | Тип           | Описание                                                                |
| -------------------------------------- | ------------- | ----------------------------------------------------------------------- |
| `receipt_id`                           | string (UUID) | ID чека с промо-инстанса                                                |
| `user_id`                              | UUID          | **Единственный атрибут участника** — ID на промо-инстансе               |
| `registration_date`                    | datetime      | Дата и время регистрации                                                |
| `purchase_date`                        | date          | Дата покупки                                                            |
| `retail_chain_id`, `retail_chain_name` | string\|null  | Торговая сеть                                                           |
| `store_inn`                            | string\|null  | ИНН магазина                                                            |
| `store_address`                        | string\|null  | Адрес магазина из ФНС                                                   |
| `total_amount`                         | number        | Общая сумма чека                                                        |
| `promo_products_amount`                | number        | Сумма акционных продуктов                                               |
| `fns_status`                           | string        | Статус ФНС                                                              |
| `moderation_status`                    | string        | Статус модерации                                                        |
| `decline_reason`                       | string\|null  | Причина отклонения (при `rejected`)                                     |
| `comment`                              | string\|null  | Комментарий последней модерации                                         |
| `fiscal_data`                          | object        | `{fiscal_number, fiscal_document_number, fiscal_sign, rrn, kkt_number}` |

**Справочники в ответе:** `retail_chains[]`, `moderation_statuses[]` (§4.1), `fns_statuses[]` (§4.2), `decline_reasons[]` (§4.3).

Фото чека в ответе нет. Данных участника (ФИО, email, код) в ответе нет — CRM их не хранит.

### 5.3. `GET api/receipts/{id}/products` — продукция в чеке

**Ключ ряда:** `gtin` позиции (строка).

**Столбцы ответа:**

| id               | title           | type              | sortable       |
| ---------------- | --------------- | ----------------- | -------------- |
| `is_promo`       | Акционный       | boolean           | да             |
| `product_name`   | Продукт         | string            | да             |
| `price`          | Цена единицы    | number (currency) | да             |
| `quantity`       | Количество      | number            | да             |
| `amount`         | Сумма           | number (currency) | да             |
| `product_status` | Статус продукта | string            | да (служебный) |

Значения `product_status`: `PENDING`, `CONFIRMED`, `CANCELLED`.

**Фильтр:** `is_promo` (options: Да/Нет).

### 5.4. `PATCH api/receipts/{id}` — решение модератора

**Тело запроса:**

```json
{
  "retail_chain_id": 42342,
  "moderation_status": "rejected",
  "decline_reason": "NO_PRODUCT",
  "comment": "В чеке нет акционных позиций",
  "products": [
    { "gtin": "4600494601234", "is_promo": true },
    { "gtin": "4600494609012", "is_promo": false }
  ]
}
```

| Поле                | Тип    | Обяз.          | Описание                                                               |
| ------------------- | ------ | -------------- | ---------------------------------------------------------------------- |
| `retail_chain_id`   | number | нет            | Уточнение сети                                                         |
| `moderation_status` | string | да             | `approved`, `rejected`, `suspended`, `need_photo`, возврат — `pending` |
| `decline_reason`    | string | при `rejected` | Код причины (§4.3); без него — `VALIDATION_ERROR`                      |
| `comment`           | string | нет            | Комментарий модератора                                                 |
| `products`          | array  | нет            | `{gtin, is_promo}` — сопоставление по `gtin`                           |

**Ответ:** `{success, message, error}`.

### 5.5. `POST api/receipts/{id}/check` — автомодерация, `DELETE api/receipts/{id}` — удаление

Оба — как в легаси, без изменений.

## 7. Границы раздела

- **Данные участника** (ФИО, email, код) недоступны в этом API: CRM-бэк хранит только `user_id`. Если панели нужно показать профиль участника, это делается отдельным запросом (к промо-инстансу или из кэша CRM) за пределами этих эндпоинтов.
- **Обратная отправка чека в промо-инстанс** после решения — интеграционный слой CRM, не часть этого API.
- **Фото чека** — панель берёт из отдельного источника по ID чека; в этом API не передаются и не хранятся.
- **`GET api/users/[id]/receipts`** — изъят из контракта (согласование ред. 3).
