# ТЗ: Панель управления

## Часть 3. Эндпоинты, используемые Панелью управления

Полный перечень эндпоинтов с параметрами, организованный по функциональным областям, зафиксированным в Части 2.

---

## 1. Общие соглашения

### 1.1. Два канала взаимодействия

| Канал                       | Компонент                        | Префикс           | Аутентификация                                         |
| --------------------------- | -------------------------------- | ----------------- | ------------------------------------------------------ |
| Канал конфигурации          | Управляющий бэкенд               | `/api/v1/...`     | Пользовательская сессия (через источник пользователей) |
| Канал операционных данных   | Административный контур инстанса | `/api/v1/crm/...` | Подпись запроса + версия обмена                        |
| Канал проведения розыгрышей | Исполнительный бэкенд            | `api/v1/...`      | Пользовательская сессия (через источник пользователей) |

### 1.2. Конверт ответов

| Тип            | Формат                                    |
| -------------- | ----------------------------------------- |
| Успех          | `{"status":"ok","data":{...}}`            |
| Ошибка         | `{"error":{"code","message","details?"}}` |
| Имена полей    | `snake_case`                              |
| Идентификаторы | UUID                                      |
| Даты           | ISO 8601                                  |

### 1.3. Общие параметры пагинации (все списковые эндпоинты)

| Параметр | Где   | Тип | По умолчанию  | Описание        |
| -------- | ----- | --- | ------------- | --------------- |
| `page`   | query | int | 1             | Номер страницы  |
| `limit`  | query | int | 20 (макс 100) | Размер страницы |

### 1.4. Общий ответ списковых эндпоинтов (в `data`)

| Поле         | Тип    | Описание                                  |
| ------------ | ------ | ----------------------------------------- |
| `items`      | array  | Массив элементов                          |
| `pagination` | object | `{page, limit, total_items, total_pages}` |

## 2. Функциональные области канала конфигурации

Все операции этого раздела выполняются через управляющий бэкенд. Управление ведётся средствами интерфейса управления; поставка данных в инстансы — задача управляющего бэкенда.

### 2.1. Управление кампаниями и инстансами

**Назначение:** регистрация инстансов, привязка к кампаниям, управление активностью.

**Канал:** управляющий бэкенд (интерфейс управления).

**Параметры инстанса, хранимые управляющим бэкендом:**

| Параметр           | Тип          | Обяз.      | Описание                                                       |
| ------------------ | ------------ | ---------- | -------------------------------------------------------------- |
| `id`               | UUID         | да (авто)  | Уникальный идентификатор инстанса                              |
| `campaign_id`      | UUID         | да         | Принадлежность к кампании                                      |
| `name`             | string       | да         | Человекочитаемое название                                      |
| `base_url`         | string (URL) | да         | Базовый URL инстанса, куда слать запросы                       |
| `is_active`        | boolean      | да         | Активен ли инстанс; при `false` поставка данных не выполняется |
| `last_sync_at`     | datetime     | нет (авто) | Время последней успешной синхронизации                         |
| `last_sync_status` | enum         | нет (авто) | `success`, `failed`, `in_progress`, `never`                    |
| `last_sync_error`  | string       | нет (авто) | Текст последней ошибки синхронизации                           |

### 2.6. Синхронизация конфигурации

**Назначение:** принудительная синхронизация конфигурации во все активные инстансы кампании.

**Канал:** управляющий бэкенд.

**Эндпоинт:** `POST /api/v1/camps/[id]/sync`

**Параметры запроса:**

| Параметр      | Где   | Тип  | Обяз. | Описание                                                               |
| ------------- | ----- | ---- | ----- | ---------------------------------------------------------------------- |
| `id`          | path  | UUID | да    | Идентификатор кампании                                                 |
| `instance_id` | query | UUID | нет   | Если указан — синхронизировать только этот инстанс; иначе все активные |

**Параметры ответа (`data`):**

| Поле                    | Тип          | Описание                                            |
| ----------------------- | ------------ | --------------------------------------------------- |
| `campaign_id`           | UUID         | Идентификатор кампании                              |
| `syncs[]`               | array        | Массив результатов по каждому инстансу              |
| `syncs[].instance_id`   | UUID         | Идентификатор инстанса                              |
| `syncs[].instance_name` | string       | Название инстанса                                   |
| `syncs[].status`        | enum         | `success`, `failed`, `skipped`                      |
| `syncs[].settings`      | object       | Сводка по настройкам: `{updated, rejected}`         |
| `syncs[].dictionaries`  | object       | Сводка по справочникам: `{added, updated, removed}` |
| `syncs[].error`         | string\|null | Текст ошибки при `status = failed`                  |
| `syncs[].duration_ms`   | int          | Длительность синхронизации в миллисекундах          |

**Механизм поставки:** поставка выполняется двумя способами — по событию изменения (автоматически) и по эндпоинту (вручную). Настройки поставляются через частичное обновление (частичное изменение значений), справочники — через модель синхронизации пула.

## 3. Функциональные области канала операционных данных

Все операции этого раздела выполняются через административный контур выбранного инстанса (префикс `/api/v1/crm/`).

### 3.1. Модель доступа к административному контуру инстанса

**Обмен односторонний:** запросы идут только от панели управления к инстансу. Пользовательской авторизации здесь нет, а в запросах ходят персональные данные участников, поэтому проверка складывается из трёх независимых слоёв.

| Слой                                       | Назначение                                   |
| ------------------------------------------ | -------------------------------------------- |
| Подпись запроса                            | Подтверждает авторство и целостность запроса |
| Окно времени с одноразовым идентификатором | Не даёт переиграть перехваченный запрос      |
| Список разрешённых адресов                 | Отсекает чужой источник                      |

**Заголовки аутентификации (обязательны для всех эндпоинтов):**

| Заголовок         | Значение                                                                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `X-Crm-Key-Id`    | Идентификатор ключа, выданного инстансом                                                                         |
| `X-Crm-Timestamp` | Время отправки, `unix`-секунды                                                                                   |
| `X-Crm-Nonce`     | Разовая строка запроса, формат: буквы, цифры, точка, подчёркивание, двоеточие, дефис; длина от 8 до 128 символов |
| `X-Crm-Signature` | Подпись запроса, шестнадцатеричная строка в нижнем регистре                                                      |

**Версионирование обмена:** каждый запрос несёт заголовок `X-Exchange-Version` с версией формата обмена в формате `A.B.C`. Инстанс с версией `V` принимает запрос, если выполняется условие `B <= V <= A`.

**Заголовок ответа инстанса:** каждый ответ несёт заголовок `X-Instance-Version` со значением версии инстанса.

**Коды ошибок доступа:**

| Статус | Код                       | Когда                                                                             |
| ------ | ------------------------- | --------------------------------------------------------------------------------- |
| 401    | `CRM_AUTH_REQUIRED`       | Не переданы заголовки подписи или недопустимый формат одноразового идентификатора |
| 401    | `CRM_KEY_UNKNOWN`         | Ключ не найден или отключён                                                       |
| 401    | `CRM_SIGNATURE_INVALID`   | Подпись не сошлась                                                                |
| 401    | `CRM_REQUEST_EXPIRED`     | Метка времени вне допустимого окна (не более 5 минут)                             |
| 409    | `CRM_REPLAY_DETECTED`     | Запрос с таким одноразовым идентификатором уже был обработан                      |
| 403    | `CRM_IP_NOT_ALLOWED`      | Адрес источника не разрешён для ключа                                             |
| 400    | `CRM_VERSION_REQUIRED`    | Отсутствует заголовок версии обмена                                               |
| 400    | `CRM_VERSION_INVALID`     | Заголовок версии некорректен                                                      |
| 409    | `CRM_VERSION_UNSUPPORTED` | Версия инстанса вне диапазона версии обмена                                       |

#### 3.2.1. `GET /api/v1/crm/users` — список участников

**Назначение:** пагинированный список участников для просмотра и управления. Поддерживает фильтрацию и поиск.

**Запрос:**

| Параметр        | Где   | Тип    | Обяз. | Описание                    |
| --------------- | ----- | ------ | ----- | --------------------------- |
| `page`, `limit` | query | int    | нет   | Пагинация                   |
| `status`        | query | string | нет   | Фильтр по статусу участника |
| `email`         | query | string | нет   | Поиск по почте              |
| `search`        | query | string | нет   | Поиск по имени/почте        |

**Ответ (`data.items[]`):**

**Запрос:**

| Параметр | Где  | Тип  | Обяз. | Описание                |
| -------- | ---- | ---- | ----- | ----------------------- |
| `id`     | path | UUID | да    | Идентификатор участника |

**Ответ (`data`):**

**Базовые данные участника:**

| Поле                                    | Тип          | Описание                                |
| --------------------------------------- | ------------ | --------------------------------------- |

| `email`                                 | string       | Почта                                   |
| `status`                                | string       | Статус участника                        |

| `extra.personal.third_name`             | string\|null | Отчество                                       |
| `extra.extended.inn`                    | string\|null | ИНН (12 цифр физлицо / 10 юрлицо)              |
| `extra.extended.snils`                  | string\|null | СНИЛС (11 цифр)                                |

- При отсутствии расширенной анкеты `extra` возвращается с пустыми структурами: `personal` и `extended` — пустые значения, `agreement` — `false`, `documents` — пустой объект. Поле `extra` не отсутствует и не `null`.

**Назначение:** создание, просмотр, редактирование, публикация, аннулирование розыгрышей, просмотр шансов, протокол розыгрыша.

**Статусы розыгрыша:** `draft` → `in_progress` → `completed` → `published`, отдельно `annulled`.

**Эндпоинты:**

| Эндпоинт                                     | Метод | Назначение                    |
| -------------------------------------------- | ----- | ----------------------------- |
| `GET /api/v1/crm/raffles`                    | GET   | Список розыгрышей             |
| `POST /api/v1/crm/raffles`                   | POST  | Создать розыгрыш              |
| `GET /api/v1/crm/raffles/[id]`               | GET   | Подробности розыгрыша         |
| `PATCH /api/v1/crm/raffles/[id]`             | PATCH | Редактировать розыгрыш        |
| `POST /api/v1/crm/raffles/publish`           | POST  | Опубликовать розыгрыш         |
| `POST /api/v1/crm/raffles/annul`             | POST  | Аннулировать розыгрыш         |
| `GET /api/v1/crm/raffles/protocol`           | GET   | Протокол розыгрыша            |
| `GET /api/v1/crm/raffles/chances`            | GET   | Все шансы                     |
| `GET /api/v1/crm/raffles/[id]/chances`       | GET   | Шансы под условиями розыгрыша |
| `GET /api/v1/crm/raffles/[id]/chances/count` | GET   | Количество шансов             |
| `GET /api/v1/crm/raffles/participants`       | GET   | Все участники розыгрышей      |
| `GET /api/v1/crm/raffles/[id]/participants`  | GET   | Участники розыгрыша           |

**Эндпоинты, используемые исполнительным бэкендом (не панелью):**

| Эндпоинт                                        | Метод | Назначение                     |
| ----------------------------------------------- | ----- | ------------------------------ |
| `POST /api/v1/crm/raffles/[id]/booking`         | POST  | Забронировать розыгрыш и шансы |
| `GET /api/v1/crm/raffles/[id]/booking/chances`  | GET   | Забронированные шансы          |
| `POST /api/v1/crm/raffles/[id]/chances/winners` | POST  | Установить победителей         |
| `PATCH /api/v1/crm/raffles/[id]/chances`        | PATCH | Обновить статусы шансов        |

#### 3.5.15. `POST /api/v1/crm/raffles/[id]/chances/winners` — установить победителей

**Запрос:**

| Параметр              | Где  | Тип    | Обяз. | Описание                     |
| --------------------- | ---- | ------ | ----- | ---------------------------- |
| `id`                  | path | UUID   | да    | Идентификатор розыгрыша      |
| `chunk_index`         | body | int    | да    | Номер порции                 |
| `is_last`             | body | bool   | да    | Признак последней порции     |
| `winners[]`           | body | array  | да    | Выигрышные шансы             |
| `winners[].chance_id` | body | UUID   | да    | Идентификатор шанса          |
| `winners[].payload`   | body | object | нет   | Данные приза и другие данные |
| `protocol`            | body | object | нет   | Протокол розыгрыша           |

**Ответ (`data`):**

| Поле            | Тип    | Описание                                                                |
| --------------- | ------ | ----------------------------------------------------------------------- |
| `raffle_id`     | UUID   | Идентификатор                                                           |
| `chunk_index`   | int    | Обработанный номер порции                                               |
| `status`        | string | Статус обработки (`accepted`, `duplicate`, `stale`, `unknown`, `error`) |
| `raffle_status` | string | Текущий статус розыгрыша                                                |

| `auth.access_token_ttl_minutes`      | int            | TTL токена доступа в минутах                                          |
| `auth.refresh_token_ttl_days`        | int            | TTL токена обновления в днях                                          |
| `raffles`                            | object         | Настройки розыгрышей                                                  |
| `raffles.raffle_chance_source_types` | string         | Источники шансов через запятую; пустая строка — шансы за все действия |
