# Пример формирования подписи

Алгоритм показан на конкретных значениях, без кода. Подпись строится как хеш с ключом от пяти строк канона, склеенных символом перевода строки.

## 1. Исходные данные

Допустим, Панель управления отправляет запрос получения списка розыгрышей:

| Аспект                    | Значение                                         |
| ------------------------- | ------------------------------------------------ |
| Метод                     | `GET`                                            |
| Путь и параметры          | `/api/v1/crm/raffles?status=draft&limit=20`      |
| Тело запроса              | отсутствует                                      |
| Секрет ключа              | 64 шестнадцатеричных символа, выданные инстансом |
| Метка времени             | `1786012345` (текущие `unix`-секунды)            |
| Одноразовый идентификатор | `0198a1c2f4b07e3d9c1a` (уникальная строка)       |

## 2. Шаг 1. Вычисление хеша тела

Для запроса **без тела** берётся хеш пустой строки. Это фиксированная общеизвестная константа:

```
Строка 3 канона = e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

Для запроса **с телом** на этом шаге вычисляется хеш фактического тела запроса (шестнадцатеричная строка в нижнем регистре).

## 3. Шаг 2. Сборка канонического вида

Канон — ровно пять строк, склеенных символом перевода строки, в строгом порядке:

| Строка | Содержание                                                                  | Значение в примере                                                 |
| ------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1      | Метод в верхнем регистре                                                    | `GET`                                                              |
| 2      | Цель запроса — путь и параметры ровно так, как отправлены, без нормализации | `/api/v1/crm/raffles?status=draft&limit=20`                        |
| 3      | Хеш тела (шестнадцатеричная строка)                                         | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| 4      | Метка времени                                                               | `1786012345`                                                       |
| 5      | Одноразовый идентификатор                                                   | `0198a1c2f4b07e3d9c1a`                                             |

Итоговый канон (строки разделены переводом строки):

```
GET
/api/v1/crm/raffles?status=draft&limit=20
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
1786012345
0198a1c2f4b07e3d9c1a
```

## 4. Шаг 3. Вычисление подписи

Подпись — это хеш с ключом (алгоритм семейства хешей с ключом) от собранного канона с использованием секрета ключа. Результат — шестнадцатеричная строка **в нижнем регистре**.

| Действие                                           | Результат                                  |
| -------------------------------------------------- | ------------------------------------------ |
| Вычислить хеш с ключом от канона, используя секрет | шестнадцатеричная строка в нижнем регистре |

Это значение и есть подпись.

## 5. Шаг 4. Итоговые заголовки запроса

Панель управления устанавливает заголовки:

| Заголовок         | Значение в примере     |
| ----------------- | ---------------------- |
| `X-Crm-Key-Id`    | `crm-prod`             |
| `X-Crm-Timestamp` | `1786012345`           |
| `X-Crm-Nonce`     | `0198a1c2f4b07e3d9c1a` |
| `X-Crm-Signature` | вычисленная подпись    |

Плюс обязательный заголовок версии обмена `X-Exchange-Version`.

## 6. Что проверяет инстанс при приёме

| Шаг проверки | Действие                                                                                                                                                                                   | Код отказа                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| 1            | Известен ли ключ, активен ли                                                                                                                                                               | Ключ неизвестен или отключён |
| 2            | Адрес источника в списке разрешённых                                                                                                                                                       | Адрес не разрешён            |
| 3            | Метка времени в окне не более 5 минут                                                                                                                                                      | Метка вне окна               |
| 4            | Формат одноразового идентификатора                                                                                                                                                         | Недопустимый формат          |
| 5            | **Подпись**: инстанс пересчитывает канон из присланного метода, цели, хеша тела, метки, одноразового идентификатора и сравнивает с присланной подписью через сравнение постоянного времени | Подпись не сошлась           |
| 6            | Версия обмена в допустимом диапазоне                                                                                                                                                       | Версия не поддерживается     |
| 7            | Одноразовый идентификатор ещё не занят                                                                                                                                                     | Запрос уже был обработан     |

## 7. Ключевые правила формирования

| Правило                                                  | Зачем                                                                                                                                   |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Подписывается цель запроса целиком, вместе с параметрами | Иначе подменой параметров можно переписать фильтры и вытащить не тот срез данных                                                        |
| Цель передаётся как отправлена, без нормализации         | Отправитель подписывает ту строку, которую кладёт в строку запроса; договариваться о порядке параметров и правилах кодирования не нужно |
| Хеш тела, а не само тело                                 | Канон остаётся коротким на порциях в мегабайты                                                                                          |
| Метка времени и одноразовый идентификатор внутри канона  | Иначе их можно подменить, и защита от повтора обходится                                                                                 |
| Сравнение подписей постоянного времени                   | Подбор подписи по времени ответа невозможен                                                                                             |
