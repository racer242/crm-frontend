Мне не хочется каждый раз мутировать конфигурацию. Хочу чтобы конфигурация была загружена полностью в память и отдавала бы любые данные для конкретной сессии быстро из памяти.
Мне нравится способ надстраивания поверх стандартной конфигурации модифицирующими частными конфигурациями в camps (как ты предложил).
Я вижу процесс так:

- при старте приложения - загружается станрдартная конфигурация (как она сейчас существует). Она может совершенствоваться в дальнейшем, но считается что это эталон
- затем, после загрузке эталона, для каждой кампании, указанной в camps, создается клон эталонной конфигурации (оцени, сколько может занять один клон в памяти). Если кампания не имеет модификаторов в camps - используется эталон
- затем, для каждой кампании с модификаторами в camps загружантся модифицирующие конфигурации.
- модифицирующие конфигурации накладываются на клон эталонной данной кампании. И с новой модифицированной конфигурацией будет вестись работа по данной кампании.

Важно чтобы наложение производилось с учетом глубины модифицируемого объекта. Так, например, если модифицируется адаптер "user.get.request" - заменятеся именно этот объект по цепочке в глубину от корня конфигурации.
Важно правильно модифицировать в массиве - например, массив страниц - если модифицируется страница или роут, каждый объект в модифицирующем массиве должен быть найден и заменен, а новый - добавлен.
Если надо удалить объект - он указывается как null. А если надо удалить объект из массива - указывается идентифицирующее поле (id для страницы или patch для роута) и поле need_to_remove:true
