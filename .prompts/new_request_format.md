## Общая схема ответа

```
Response
├── columns[]          — описание колонок таблицы
├── rows[]             — данные (строки таблицы)
├── filters[]          — описание фильтров + их текущие значения
├── search             — поисковый запрос (строка)
└── meta               — пагинация и сортировка
```

## 1. `columns[]` — описание колонок

```
{
  id: string,            // идентификатор колонки (используется как ключ в values)
  title: string,         // заголовок для UI
  type: 'string' | 'date' | 'number',   // тип отображения
  sortable: boolean,     // можно ли сортировать
  props: object          // доп. настройки (пока пусто)
}
```

Ключевой момент: `id` колонки = ключ в `values` строки. Это контракт — как колонка называется в `columns`, так и должна называться в `values`.

## 2. `rows[]` — строки данных

```
{
  id: number,            // внутренний номер строки (НЕ UUID!)
  values: {
    [column.id]: any     // значения по ключам из columns[].id
  }
}
```

Особенности:

- `id` строки — технический (порядковый номер), UUID лежит внутри `values` как отдельная колонка.
- Для enum-полей часто есть парное поле `<field>_label` с человекочитаемым значением (например, `fns_status` + `fns_status_label`).
- Даты приходят в ISO-8601 с часовым поясом (`+03:00`).
- Деньги — уже в рублях (не в копейках, как в БД). То есть API делает `/100` на своей стороне.

## 3. `filters[]` — описание фильтров

Типы фильтров и формат их `value`:

| `type`     | `opts`          | `value`                       | Смысл                                           |
| ---------- | --------------- | ----------------------------- | ----------------------------------------------- |
| `options`  | массив подписей | массив `boolean` той же длины | Мультивыбор: `true` на позиции = опция включена |
| `period`   | `null`          | `null` или `[from, to]`       | Период (две даты)                               |
| `range`    | `[min, max]`    | `[min, max]`                  | Числовой диапазон                               |
| `checkbox` | `null`          | `null` или `boolean`          | Одиночный чекбокс                               |

Фильтры возвращаются в ответе с их текущими значениями — это значит, что UI может восстановить состояние формы из ответа.

## 4. `meta` — пагинация

```
{
  total_count: number,   // всего строк (для пагинатора)
  first: number,         // смещение (offset)
  limit: number,         // размер страницы
  sort: string,          // поле сортировки (= column.id)
  direction: 'asc' | 'desc'
}
```

## 5. Запрос (GET)

Параметры URL:

- `event` — JSON (дублирует `filters`, видимо, для глубокой ссылки)
- `first`, `rows` — пагинация
- `sortField`, `sortOrder` (1 / -1) — сортировка
- `filters` — JSON-массив фильтров

На сервере это превращается в:

```
{
  first, limit,
  sort,                // = sortField
  direction: 'asc' | 'desc',   // sortOrder: 1 → asc, -1 → desc
  search,
  filters: [{ id, value }]
}
```

## Ключевые соглашения, которые я запомнил

1. **Контракт «колонка ↔ значение»**: `columns[].id` = ключ в `rows[].values`.
2. **Даты** — ISO-8601 с TZ, деньги — в рублях (float), идентификаторы — строковые UUID.
3. **Enum-поля** — машинное значение + `_label` для отображения.
4. **Фильтр `options`** — булевый массив по позициям `opts`, а не массив выбранных значений. Это важно при проектировании — такой формат фиксирует порядок опций.
5. **`meta.total_count`** — для пагинатора, `first/limit` — для offset-пагинации (не курсорной).
6. **`filters` в ответе** — состояние формы, можно восстанавливать UI из ответа.
